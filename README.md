# Сбор и приоритизация общедоступных IoC

Тестовое задание для БКС на Python. `collect.py` собирает индикаторы из
**PhishTank, ThreatFox и MalwareBazaar**, нормализует их и сохраняет в локальную
SQLite. `ioc.py` выводит индикаторы по приоритету и экспортирует результаты.

Совпадение — это одинаковая пара **тип + нормализованное значение**.
Приоритет (`level`) рассчитывается строго по правилу ТЗ:

| Различных источников | Уровень |
| --- | --- |
| 3 и более | Critical |
| 2 | High |
| 1 | Medium |

Уровня Low в задании нет. Этот приоритет отражает количество источников,
а не тяжесть атаки, уверенность поставщика или разрешение на автоблокировку.

Поддерживаются `ipv4`, `ipv6`, `domain`, `url`, `ip_port`, `md5`,
`sha1`, `sha256`. В текущей тройке сетевые адреса ThreatFox обычно представлены
как `ip_port`; отдельный IP не выводится из пары автоматически.

## Быстрый запуск без ключей и интернета

Нужны **Python 3.10+** и SQLite **3.31+** в стандартном модуле `sqlite3`.
Сторонних библиотек нет: установка через pip не требуется.
Команды выполняются из каталога проекта; на Windows вместо `python`
можно использовать `py -3`, на Linux — `python3`.

```shell
python collect.py --demo
python ioc.py --db data/demo.sqlite3 --level high
python ioc.py --db data/demo.sqlite3 --level medium
python ioc.py --db data/demo.sqlite3 --level critical
python ioc.py --db data/demo.sqlite3 --stats
```

Демо использует синтетические файлы в форматах настоящих источников:
**11 уникальных IoC: 3 High, 8 Medium, 0 Critical**.
Ссылки ведут в документационные домены, IP взяты из документационных диапазонов,
хеши вымышлены. Никакие вредоносные файлы не скачиваются.
Данные demo и live нельзя смешивать в одной БД.

## Почему выбраны эти три источника

**Выбор обоснован следующими критериями:** требовалось выбрать три бесплатных
открытых источника, стремясь к максимально широкому покрытию типов IoC и
полезных сценариев обнаружения в рамках тестового задания. При этом нужны
пересечения по типам, чтобы можно было показать сопоставление индикаторов и
повышение их приоритета. Если каждый источник содержит исключительно свой
непересекающийся тип, все индикаторы всегда получат Medium.

Выбранные источники дают фишинговые URL, сетевые индикаторы вредоносной
инфраструктуры и хеши файлов. Пересечения URL между PhishTank и ThreatFox и
хешей между ThreatFox и MalwareBazaar позволяют демонстрировать High.
Совпадение типов создаёт возможность сопоставления, но не гарантирует
совпадения конкретных значений в очередной загрузке.

Под «открытыми» здесь понимаются общедоступные данные и документированные
интерфейсы, а не отсутствие регистрации или любых условий использования.
Бесплатный community-доступ abuse.ch предусмотрен для подходящих сценариев
Fair Use; бесплатность промышленной эксплуатации в коммерческой компании
**не гарантируется**. Наличие бесплатного ключа этому ограничению не противоречит.

| Источник | Какие данные собираются | Покрываемая задача | Пересечение |
| --- | --- | --- | --- |
| PhishTank | URL подтверждённых действующих фишинговых страниц | Поиск опасных ссылок в письмах и веб-трафике, защита учётных данных сотрудников | URL с ThreatFox |
| ThreatFox | IP:port, домены, URL, опубликованные хеши | Обнаружение инфраструктуры управления ВПО и доставки вредоносных файлов | URL с PhishTank, хеши с MalwareBazaar |
| MalwareBazaar | SHA-256, SHA-1, MD5 образцов | Поиск известных вредоносных файлов на почтовом шлюзе и конечных устройствах | Хеши с ThreatFox |

### PhishTank

Выбран для покрытия фишинга: URL позволяет сохранить точный путь к опасной
странице, не превращая весь общий хостинг в блокируемый ресурс. Из CSV берётся
только поле `url` записей с `verified=yes` и `online=yes`.
Ссылки на карточки PhishTank и названия атакуемых брендов не считаются IoC.

Выгрузка обновляется ежечасно. Без ключа допускается лишь несколько скачиваний
в день; для существующего ключа приложения поддерживается переменная
`PHISHTANK_APP_KEY`. Новая регистрация на дату проверки закрыта, поэтому
проект умеет работать с публичной выгрузкой, но не обещает её частый опрос.

Источники: [документация выгрузок](https://phishtank.org/developer_info.php),
[страница регистрации](https://phishtank.org/register.php),
[FAQ об использовании данных](https://phishtank.org/faq.php).

### ThreatFox

Выбран как источник нескольких типов IoC, связывающий URL и файловые хеши
с сетевой инфраструктурой вредоносного ПО. Импортируются явно типизированные
поля `ioc` / `ioc_type`. Порт сохраняется: `192.0.2.1:443` не заменяется
более широким индикатором `192.0.2.1`.

Используется документированный API-запрос `get_iocs` с `days=7`, максимальным
окном этого метода. Это индикаторы, впервые добавленные за последние семь дней,
**не полный перечень всей активной инфраструктуры**. API требует бесплатный
`Auth-Key`. ThreatFox исключает из API/экспорта индикаторы старше шести месяцев;
это политика поставщика, а не реализованный в нашем приложении TTL.

Источники: [API ThreatFox](https://threatfox.abuse.ch/api/),
[экспорт и срок актуальности](https://threatfox.abuse.ch/export/).

### MalwareBazaar

Выбран для файлового уровня обнаружения: сетевые списки не заменяют проверку
известных вредоносных вложений и исполняемых файлов. Из CSV извлекаются
`sha256_hash`, `sha1_hash`, `md5_hash`. Значения разных алгоритмов остаются
разными индикаторами; название семейства или ссылка на анализ не подменяют хеш.

Загружается `recent.csv`: хеши добавлений за последние 48 часов, обновление
выгрузки — каждые пять минут. Это ограниченная по времени выборка для
воспроизводимого консольного запуска, не полный исторический архив.
Нужен тот же `ABUSECH_AUTH_KEY`. Сами образцы вредоносного ПО не загружаются.

Источники: [экспорт MalwareBazaar](https://bazaar.abuse.ch/export/),
[API и описание полей](https://bazaar.abuse.ch/api/).

### Пересечения и ограничения приоритета

ThreatFox и MalwareBazaar — разные наборы данных одной экосистемы abuse.ch.
В рамках ТЗ они считаются двумя источниками, но их совпадения **не являются
доказательством независимого подтверждения**. Повторы строк, несколько файлов
одного источника или разные записи одного IoC не увеличивают `source_count`.

У PhishTank в этом импорте только URL, у MalwareBazaar только хеши.
Общего типа у всех трёх нет, поэтому **Critical в текущей конфигурации не
возникает**. Мы не извлекаем домены из URL или ссылки на отчёты из метаданных
ради искусственного повышения приоритета. Демо показывает реальные для этих
форматов пересечения High и одиночные Medium; переход Medium → High → Critical
проверяется отдельным тестом на трёх явно условных источниках.

### Применимость к БКС

Выбор ориентирован на кражу учётных данных, вредоносные вложения и связь
заражённых устройств с инфраструктурой управления. Эти классы угроз значимы
для финансового сектора: в [обзоре Банка России за 2024 год](https://www.cbr.ru/Collection/Collection/File/55129/Attack_2024.pdf)
рассматриваются компрометация учётных данных, ВПО для удалённого управления,
кражи данных и шифровальщики.

Полнота покрытия именно БКС и российского финансового сектора этой тройкой
не подтверждена. Её нужно оценивать на корпоративной телеметрии, а не по стране
поставщика, геолокации IP или доменной зоне. Корпоративный фильтр также не
защищает автоматически личные устройства клиентов за пределами инфраструктуры.

[Securelist](https://securelist.ru/head-mare-phantomheart-and-phantomproxylite/114753/)
публикует открытые расследования с IoC и может дополнить региональный контекст,
но отдельные статьи не равны постоянно обновляемому фиду активных индикаторов.
Закрытые корпоративные TI-сервисы и отраслевой обмен ФинЦЕРТ не включены
в обязательную тройку: для запуска тестового нельзя предполагать доступ
проверяющего к ним.

Три списка известных IoC не заменяют полноценную защиту: новые индикаторы,
скомпрометированные легитимные сервисы и атаки без известных артефактов могут
не обнаружиться. Решение собирает данные, но не устанавливает правила блокировки.

## Сетевой сбор и API-ключи

1. Получите бесплатный Auth-Key через [портал abuse.ch](https://auth.abuse.ch/).
   Доступ зависит от текущих условий сервиса и его Fair Use.
2. Задайте `ABUSECH_AUTH_KEY` в окружении процесса, запускающего Python.
   Личный ключ не нужно передавать проверяющему: он использует собственный.
3. При наличии уже выданного ключа PhishTank задайте `PHISHTANK_APP_KEY`.
   Без него используется ограниченная публичная выгрузка.

PowerShell:

```powershell
$env:ABUSECH_AUTH_KEY = "ваш-ключ"
# Необязательно, только если такой ключ уже есть:
# $env:PHISHTANK_APP_KEY = "ваш-ключ-приложения"
python collect.py
python ioc.py --stats
python ioc.py --level high
```

Linux/macOS:

```shell
export ABUSECH_AUTH_KEY="ваш-ключ"
python3 collect.py
```

Ключи не задаются в исходниках или аргументах CLI и не записываются в БД.
Логи HTTP-ошибок содержат имя сервера, но не URL с ключом или заголовки
авторизации. Файл `.env` автоматически не читается и исключён из Git.
Вместо сохранения реального ключа в истории команд можно задать переменную
через используемый менеджер секретов или настройки окружения.

База создаётся в `data/iocs.sqlite3`; относительные пути отсчитываются от
текущего каталога. Без `ABUSECH_AUTH_KEY` PhishTank обрабатывается самостоятельно,
а два остальных источника получают понятную ошибку конфигурации. Сбор частично
успешен, если хотя бы один источник загрузился. Существующие снимки источников
с ошибкой сохраняются. Скрытого переключения на устаревшие безключевые адреса нет.

Требование бесплатности выполнено для учебного community-сценария в рамках
условий сервисов, а не как обещание бесплатного корпоративного SLA.
[Условия abuse.ch](https://abuse.ch/terms-of-use/) допускают необходимость
платной подписки для коммерческого применения. Возможность использования ключа
на другом компьютере зависит от условий сервиса, лимитов и сетевого доступа;
привязка к одному компьютеру в программе не реализована.

Условия источников проверены **16.09.2026**. Они могут измениться.

## Команды, вывод и экспорт

```shell
python collect.py --db data/custom.sqlite3 --timeout 30 --retries 2
python ioc.py --stats
python ioc.py --level high --limit 20 --offset 0
python ioc.py --level medium --limit 0 --format json --output data/medium.json
python ioc.py --level high --format csv --output data/high.csv
python ioc.py --level medium --format txt --output data/medium.txt
```

`--level` принимает Critical, High, Medium без учёта регистра.
По умолчанию показываются первые 100 записей; `--limit 0` означает все.
JSON содержит также `source_details`: состояние и время успешного сбора
источников. CSV и таблица сохраняют типы; TXT содержит только значения, поэтому
для дальнейшей обработки смешанных типов предпочтительнее JSON/CSV.

Заголовки и строки таблицы имеют одинаковые ширины колонок; длинные значения
в интерактивном терминале переносятся внутри колонок. Для файлов и перенаправления
ширина не ограничивается размером окна. Для очень узких окон удобнее JSON/CSV.

`INFO` — обычная диагностика, а не ошибка. Строка `source/feed` описывает
конкретную загрузку, строка `source: OK` — итог источника. `values` — число
проверяемых значений IoC (в одной записи MalwareBazaar их три), `unique` —
число уникальных валидных IoC, `duplicates` — повторы, `invalid` — отклонённые
значения. `skipped` — записи PhishTank с неподходящим статусом.
Логи пишутся в stderr, результаты — в stdout.

Коды завершения сбора: **0** — все источники успешны; **2** — частичный успех;
**1** — все источники недоступны либо ошибка БД; **130** — прерывание.
У argparse код **2** также обозначает неверные аргументы команды.

## Нормализация

- Пробелы по краям удаляются; внутренние пробельные и управляющие символы
  отклоняются. Восстанавливаются разделители `[.]`, `(.)` и схемы `hxxp(s)`.
- IP проверяются стандартным `ipaddress`; IPv6 сжимается. Scoped IPv6 отклоняется.
- Домены приводятся к нижнему регистру и ASCII/IDNA, конечная точка удаляется.
  Поддомены не склеиваются с родительским доменом.
- URL сохраняет схему, путь, регистр пути, порядок параметров, escapes и fragment.
  Нормализуются схема/хост; стандартный порт удаляется, пустой путь становится
  `/`. URL не превращается в домен или IP.
- `ip_port` сохраняет порт; IPv6 записывается как `[адрес]:порт`.
  Пара адрес/порт и отдельный IP — разные индикаторы.
- Хеш проверяется по алфавиту и точной длине своего алгоритма, затем переводится
  в нижний регистр. Хеши разных алгоритмов не объединяются.

Ключ `UNIQUE(type,value)` исключает дубли, а ключ
`PRIMARY KEY(indicator_id,source_id)` исключает повторный учёт источника.
Проверяется синтаксис, а не вредоносность или глобальная маршрутизируемость IP.
Доменам не выполняются DNS-запросы, переходов по IoC нет.
Встроенный IDNA-кодек Python реализует IDNA 2003.

## SQLite и повторный сбор

Используется **простая локальная встраиваемая СУБД SQLite**. Разворачивать
отдельный сервер, устанавливать PostgreSQL/MySQL, поднимать службу или контейнер
не требуется. SQLite — полноценная СУБД с SQL, индексами и транзакциями, но
работает библиотекой внутри процесса Python.

В обычной поставке Python уже доступны модуль `sqlite3` и библиотека SQLite.
`sqlite3.connect(...)` создаёт файл, SQL из `SCHEMA` в
`ioc_collector/database.py` создаёт таблицы и индексы. Исходники SQLite скачивать
и компилировать не нужно. Создание пустой структуры быстрое; основное время
занимает загрузка и запись индикаторов. Для нескольких параллельных писателей
архитектуру следует пересмотреть: [рекомендации SQLite](https://www.sqlite.org/whentouse.html).

Таблицы: `indicators` — IoC и приоритет; `observations` — связи с источниками;
`sources` — состояние сбора; `metadata` — версия схемы и режим demo/live.
`level` — хранимая вычисляемая колонка, зависящая от `source_count`.

Каждый успешный сбор атомарно заменяет снимок одного источника:
добавляет новые связи, удаляет исчезнувшие, пересчитывает приоритет и удаляет
IoC без источников. Повторы внутри источника не повышают приоритет.
Ошибка загрузки или формата сохраняет предыдущий успешный снимок.

Для ThreatFox и MalwareBazaar снимок ограничен описанным выше окном.
Исчезновение из такого окна **не означает, что индикатор стал безопасным**.
Текущая версия не является накопительным архивом всех когда-либо найденных IoC.

`first_seen`, `last_seen` и `updated_at` — времена локальной обработки в UTC,
не даты активности угрозы у поставщика. История удалённых связей, контекст
кампаний и отдельный TTL пока не реализованы. При длительном сбое сохранённые
данные могут устареть; CLI предупреждает, `--stats` показывает `last_success`.

### Переход с прежней версии

Схема v2 добавляет новые типы. При первом сборе со старой БД схема v1
автоматически копируется средствами SQLite в соседний файл
`имя.sqlite3.v1-XXXXXXXX.bak`, затем мигрируется с сохранением записей и связей.
При ошибке резервного копирования миграция не начинается.

Перед полным сбором записи прежних источников Blocklist.de, CINS Army и
ThreatView исключаются из рабочей БД: они не должны превращать новую тройку
в шесть источников или завышать приоритет. Старые данные остаются в резервной
копии. Чтение через `ioc.py` само по себе не мигрирует старую БД.
Резервные копии и рабочие БД исключены из Git.

## Надёжность и проверка

HTTPS и проверка TLS включены. Перенаправления ограничены тем же сервером
и известным HTTPS CDN PhishTank. Ключи не отправляются произвольному другому
серверу. Временные сетевые ошибки и HTTP 408/429/5xx повторяются ограниченно;
учитывается `Retry-After`, максимум 30 секунд. По умолчанию два повтора.

Размер ответа ограничен 32 МиБ. Неверный CSV/JSON, HTML вместо фида,
обрыв загрузки и более 10% невалидных значений отклоняются.
Пустые CSV отклоняются как подозрительные; явный ответ ThreatFox `no_result`
или успешный пустой массив корректно очищает его снимок. Ошибки API не
трактуются как пустые успешные ответы.

```shell
python -m unittest discover -s tests -v
```

Тесты не требуют сети и ключей. Проверяются форматы трёх источников,
нормализация, пересечения, все уровни приоритета, частичные ошибки, сохранение
снимков, удаление устаревших связей, миграция с резервной копией, защита ключей,
HTTP-повторы и запуск CLI.

Примеры: `examples/demo_run.txt`, `examples/live_run.md`,
`examples/live_stats.json`. Сетевой пример явно указывает, какие источники
проверены, а какие недоступны из-за отсутствия ключа.
Ответы на вопросы ТЗ: [ANSWERS.md](ANSWERS.md).

## Структура

```text
collect.py                  Сбор
ioc.py                      Запросы и экспорт
ioc_collector/sources.py     Источники и параметры запросов
ioc_collector/feeds.py       HTTPS, повторы, CSV/JSON-парсеры
ioc_collector/normalize.py   Нормализация типов IoC
ioc_collector/database.py    SQLite, миграция и транзакции
ioc_collector/collector.py   Независимая обработка источников
ioc_collector/cli.py         Команды и вывод
examples/                   Синтетические данные и примеры запусков
tests/                      Проверки без сети
```
